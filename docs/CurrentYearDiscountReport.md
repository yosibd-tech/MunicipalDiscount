# דוח ניתוח הנחות בשנה השוטפת — מקור כל עמודה וחישובה

**במחלקה:** `Classes/CurrentYearDiscountAuditReport.cs`
**בסרגל:** *דוחות* → `barButReportCurrentYear`
**פלט:** `ניתוח_הנחות_שנה_שוטפת_<שנה>_<חותמת>.xlsx` + `.pdf` בתיקיית הדוחות
(`C:\MunicipalDiscount\Reports`, מוצגת בסייר כ־**דוחות**)

הדוח מאתר תושבים שקיבלו הנחה **גדולה מהמותר בחוק**. אותו חישוב מזין את
`GenerateLetters`, שמפיק לכל שורה מכתב דרישה עם הנוסח שב־`IllegalDiscountMessage`:
*"קבלת הנחה לא חוקית בסך {סכום}, נא לבוא לסדר את החוב שנוצר עקב כך ולמנוע הליכי
אכיפה"*. כלומר: כל שורה בדוח היא דרישת תשלום מתושב.

---

## אילו שורות נכנסות לדוח

הדוח עובר על **כל בקשות ההנחה של השנה** (`tbDiscountRequests` שמצורפות ל־
`tbYearlyDiscounts` עם `Year_ = @year`), ומשאיר רק את אלה שעוברות שני תנאים:

```sql
WHERE rpt.IllegalDiscount > 0
  AND rpt.IllegalDiscount >= rpt.CurrentYearBlling * 0.02
```

1. ההנחה בפועל **גדולה** מההנחה החוקית.
2. ההפרש הוא **לפחות 2%** מהחיוב השנתי — סף שנועד לבלוע הפרשי עיגול.

אם אין אף שורה, לא נוצר קובץ כלל ומוצגת ההודעה *"לא נמצאו נתונים לשנת X"*.

> **שים לב:** כאשר `AnnualBilling` הוא NULL, התנאי השני מחזיר UNKNOWN והשורה
> **נושרת בשקט** — בלי ספירה ובלי אזהרה. ראה "תקלות ידועות" בהמשך.

## מקורות הנתונים

| טבלה / תצוגה | מה מגיע ממנה | מי ממלא אותה |
|---|---|---|
| `tbDiscountRequests` | הבקשה: קוד ההנחה, הסכום בפועל, החלטת העובד | קליטת דוח 203 |
| `tbYearlyDiscounts` | הנכס: מספר, גודל, חיוב שנתי | קליטת ההנחות + קליטת החיוב |

`vwDiscountRateAsOf` היא **INNER JOIN** בין `tbDiscountsCodes` ל־
`tbDiscountCodeRates`, ומחשבת לכל גרסה את תאריך סיומה ב־`LEAD(ValidityDate)`.
קוד ללא אף שורת תעריף אינו מופיע בה כלל.

## החישוב, שלב אחר שלב

### שלב א' — איתור גרסת התעריף שחלה

```sql
OUTER APPLY (
    SELECT TOP 1 v.DiscountName, v.MaximumArea, v.DiscountPercent, v.MaximumDiscount
    FROM   vwDiscountRateAsOf v
    WHERE  v.MunicipalDiscountCode = r.MunicipalDiscountCode
      AND (r.RequestDate IS NULL
           OR (r.RequestDate >= v.RateFrom
               AND (v.RateUntil IS NULL OR r.RequestDate < v.RateUntil)))
    ORDER BY v.RateFrom DESC
) rate
```

הגרסה נבחרת לפי **תאריך הבקשה**, כך שתעריף שהשתנה באמצע השנה מיושם נכון.
כשאין תאריך בקשה — נלקחת הגרסה החדשה ביותר.

### שלב ב' — הגבלת האחוז לתקרה החוקית

```sql
EffectiveRate = CASE WHEN MaximumDiscount < DiscountPercent
                     THEN MaximumDiscount ELSE DiscountPercent END
```

האחוזים שמורים כשברים (`0.7` ולא `70`). קוד שמעניק 80% עם תקרה של 70% נותן
`0.7`. זו הסיבה שקודי ה־80% חוזרים ומופיעים בדוח: העירייה נתנה 80, החוק מתיר 70.

### שלב ג' — הפעלת תקרת השטח

```sql
CASE
    WHEN AssetSize IS NULL OR AssetSize = 0
      OR AnnualBilling IS NULL OR AnnualBilling = 0   THEN 0
    WHEN AssetSize > MaximumArea AND MaximumArea > 0
      THEN (AnnualBilling / AssetSize) * MaximumArea * EffectiveRate
    ELSE  AnnualBilling * EffectiveRate
END AS LegalDiscountAmount
```

נכס גדול מהתקרה מקבל הנחה על **חלק יחסי** של החיוב: נכס 251 מ"ר עם תקרה של
100 מ"ר מקבל הנחה על שווי החיוב של 100 מ"ר בלבד.

### שלב ד' — ההפרש

```sql
IllegalDiscount = ABS(ActualDiscountAmount) - LegalDiscountAmount
```

## תקלות ידועות — לקריאה לפני שליחת מכתבים

נמדד מול נתוני 2026 החיים. הדוח מסמן **1,043 תושבים על סך 1,828,633 ₪**.

### 1. קוד ללא שורת תעריף נחשב כזכאי לאפס — 277 שורות, 1,062,669 ₪

`vwDiscountRateAsOf` היא INNER JOIN. לקוד בלי תעריף אין בה שורה, `EffectiveRate`
יוצא NULL, ושלב ג' מחשב `AnnualBilling * ISNULL(NULL, 0)` — **זכאות אפס**. כל
ההנחה מדווחת כלא חוקית.

הקודים במצב הזה: **567** (246 קשישים, 1,027,659 ₪), **543**, **505**, **581**,
**435**, **370**. כולם הנחות לגיטימיות. הדוח אינו מבחין בין "אין זכאות" לבין
"הזכאות לא ידועה", ומדווח על שתיהן כגניבה.

### 2. זיכוי נספר כהנחה — 34 שורות

שלב ד' מפעיל `ABS()`. בדוח 203 יש גם סכומים חיוביים — תיקונים ש**חייבו את
התושב בחזרה**. 294 בקשות ב־2026 הן כאלה, ו־`ABS` הופכת כל אחת להנחה באותו גודל.

### 3. הנחת שנים קודמות נמדדת מול חיוב שנה אחת — 21 שורות, 37,264 ₪

הנחה יכולה לחול על שנה קודמת. דוח 203 מבחין בין השורות לפי **שנה מקורית**,
עמודה שאינה נשמרת במסד. 21 שורות מסומנות שבהן ההנחה גדולה מכל החיוב השנתי —
בלתי אפשרי לשנה אחת.

### 4. חיוב אפס מייצר זכאות אפס — שורה אחת

כש־`AnnualBilling = 0`, שלב ג' מחזיר 0 וגם הסף הוא 0 — כל ההנחה מסומנת ותמיד
עוברת. בנוסף, **96 בקשות עם חיוב NULL נושרות מהדוח לגמרי**, ללא ספירה.
