## Build & Run

```bash
# Build
dotnet build MunicipalDiscount.csproj

# Run
dotnet run --project MunicipalDiscount.csproj
```

There are no unit tests in this project.

### Python scripts

All are launched from the app's toolbar buttons (via `ManParameters.PythonScriptsPath`)
and can also be run by hand.

```bash
# Previous-year discounts file -> tbClients / tbYearlyDiscounts / tbDiscountRequests
# Requires: pandas, pyodbc
python PythonScripts/import_discounts.py <file_path> <user_identity_card> [header_row]

# Discount codes round trip -> two workbooks. Requires: openpyxl, pyodbc
python PythonScripts/export_discount_codes.py <codes.xlsx> <rates.xlsx>
python PythonScripts/import_discount_codes.py <codes.xlsx> <rates.xlsx> --dry-run
python PythonScripts/import_discount_codes.py <codes.xlsx> <rates.xlsx> --replace
```

The workbook layout is documented in `docs/DiscountCodes_Excel_Format.md` — that is
also how one municipality's codes are carried to another. `--replace` empties the
code tables first; the two files are the complete picture, not a delta.

## Architecture

This is a **Windows Forms (.NET 8.0) desktop application** for managing municipal discount eligibility in Israel. It uses **DevExpress v25.2.3** for UI controls and **SQL Server** as the database backend.

### Key patterns

- **MDI (Multiple Document Interface):** `MainForm` is the MDI parent; all other forms open as child windows inside it.
- **Session state:** `SessionData` (static class) holds the currently selected municipality, employee, and year. Most child forms depend on these values being set before opening.
- **Direct SQL:** No ORM. All database access uses `Microsoft.Data.SqlClient` with parameterized queries. Connection string is centralized in `DatabaseConfig.cs`.
- **Hebrew RTL:** The entire UI is in Hebrew with right-to-left layout. All user-facing strings, labels, and validation messages must be in Hebrew.
- **Theming:** `ThemeHelper` applies a consistent Bezier color scheme across controls. New forms should call `ThemeHelper.ApplyTheme()` after `InitializeComponent()`.
- **Data import pipeline:** Excel files are imported via a Python script (`import_discounts.py`) that reads column mappings from `tbDiscountHeaders`, joins discount codes, and bulk-inserts into `tbYearlyDiscounts`.

### Core files

| File | Purpose |
|------|---------|
| `Program.cs` | Entry point; initializes DevExpress skin and launches MainForm |
| `Classes/DatabaseConfig.cs` | Centralized SQL Server connection string |
| `Classes/SessionData.cs` | Static session state (municipality, employee, year) |
| `Classes/ThemeHelper.cs` | Recursive UI theme application |
| `Classes/DiscountEligibilityReport.cs` | Report generation logic |
| `Forms/MainForm.cs` | MDI parent with ribbon toolbar and session selectors |

### Database tables (primary)

- `tbDiscountsCodes` — Discount definitions by category and year
- `tbDiscountHeaders` — Excel column-to-discount mappings
- `tbYearlyDiscounts` — Imported annual discount records
- `tbMinimumWage` — Minimum wage values by year
- `tbIncomeDiscountCriteria` — Income bracket thresholds for discounts

## Conventions

- Form files live in `Forms/`, business logic classes in `Classes/`
- Each form has a `.cs`, `.Designer.cs`, and `.resx` file — only edit the `.cs` file manually; `.Designer.cs` is auto-generated by the WinForms designer
- DevExpress controls are used throughout (GridControl, RibbonControl, LayoutControl, etc.) — use DevExpress equivalents rather than standard WinForms controls
- Validation messages and UI text must be in Hebrew
