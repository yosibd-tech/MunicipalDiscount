**How it works on the server:**

**- New installer section: under the collection app there's a ticked checkbox for the scheduled tasks. It asks for a Windows account, filled in with the current user, and that account's password.**

**- What gets registered: the same four names and times, pointing at the installed YBD. They'll appear in YBD's  תיזמון משימות .screen as before** 

**- The password goes straight to Windows, which needs it to run tasks while nobody is logged on. It never appears on a command line. If the account's password changes later, run the installer again.**

**- Running the installer again replaces the tasks and never duplicates them.**

**- Something wrong in the current tasks: each has the program path written twice in its arguments. They work anyway. YBD's current code no longer does this, and the server tasks are written correctly.**



**When you move to the new computer:**

**1. Disable the four tasks on your development computer in Task Scheduler, both the old one and the new one. Otherwise every run happens twice and the manager gets two emails.**

**2. The daily import files (report 24, bank foreclosures, arrangements) must go into the server's import folders from now on.**

**3. Every appsettings.json in the three repos holds a password encrypted for this computer only, and it won't decrypt on the new one. Run the three SecretsSetup tools there once before building.**

**4. Editing a task from YBD's scheduling screen switches it back to "only when logged on", because that screen always writes it that way. Change times in Windows Task Scheduler instead, or I can fix YBD's screen.**

**לגבי מחשב עובדים עם דף הנחות**

is workers who operat only web page need installetion

No. Workers who only use the web page don't install anything.

**A worker needs:**

1\. A browser such as Chrome or Edge, which every Windows computer already has.

2\. To be on the same network as the computer where you ran the installer.

3\. The address: http://<server-computer-name>:5000, for example http://DESKTOP-MUPUTRI:5000. If the name isn't found, use the server's IP address instead, like http://192.168.1.20:5000.

4\. A user name and password, the same ones as in the desktop app (the tbUsers table).

Worker computers don't need .NET, SQL Server, the installer or any files. They also never get the database password, which stays only on the server.

For convenience you can put a desktop shortcut to that address on each worker's computer. That's optional.

The installer is only for the one server computer, the manager's machine that runs SQL Server.


נושאים לטיפול לבדיקת התקנת הנחות על מחשב חדש

1\. The database. A fresh SQL Server Developer install is empty. The installer only tests the connection and writes parameters; it never creates the MunicipalDiscount database. You'll need to bring a backup (.bak) from this machine and restore it there first. That also covers the tables MonicipalYBD uses, since both apps share one database.

2\. SQL login mode. Developer edition installs with Windows sign-in only by default. The installer connects with a SQL user and password, so choose Mixed Mode during the SQL install and create that login.

3\. ASP.NET Core Runtime 8. The installer checks for it and stops if it's missing. Download it from Microsoft before you start.

4\. The files to carry over: the published web app folder, the installer .exe, and the desktop app if you want it there too. I'll prepare this as one ready-to-copy folder.

5\. The population-registry file, YOSSI-APP-DATA.xlsx, copied into the folder the installer creates.
